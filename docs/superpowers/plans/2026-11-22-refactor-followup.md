# 우선순위별 후속 리팩토링 계획

목표: 기존 동네·수동 편집·에셋 ID·외형을 유지하며 재현 가능한 빌드와 생성/화면 책임 경계를 정리하고 공개 확인까지 완료한다.

사용자가 지정한 실행 방식: 같은 작업자 한 명에게 한 태스크씩 지시한다. 부모가 변경 내용과 검사를 직접 검토한 뒤 다음 태스크를 승인한다. 별도 리뷰 에이전트는 만들지 않는다.

## 공통 조건

- 기준 폴더와 main을 사용한다. 시작 시 다른 대화의 작업을 별도 원문/해시로 보존한다. 전체 add/reset/clean/stash를 하지 않는다.
- 이미 완료한 refactor-20261122 변경은 다시 적용하지 않는다. 작업 기록은 verification/refactor-followup-20261122에 둔다.
- 생성 시 길 위 관찰점의 360도 시야, 도로 우선, 확인 정보와 수동 지정값 우선을 유지한다.
- 생성 파일은 정식 원본에서 재생성한다. 새 모듈은 Python pack 또는 공개 파일 명세에 연결한다.
- 커밋은 부모가 선택 트리로 검토한다. 다른 대화의 staged 파일과 공유 파일의 외부 변경은 공개하지 않는다.
- 실패/취소/저장 오류를 성공으로 바꾸지 않는다. 성능 효과를 측정 없이 주장하지 않는다.

## 태스크와 완료 조건

1. JavaScript 생성 묶음: 고정 버전 도구로 재현 가능한 빌드와 최신성 검사를 제공한다. 쿼리 버전별 같은 모듈 중복을 없애고 실제 원본 변경으로 검사가 실패하는지 확인한다. 기존 Python 묶음 검사와 CI/공개 빌드에 연결한다.
2. 도로 기하: arterial_plan의 출입구/횡단부 계산을 명시적인 입력·결과를 가진 모듈로 분리한다. 정상 기하 보존과 빈 면·여러 조각·구멍·경사를 검사한다. 원본 시설은 보존하고 생략 사유를 기록한다. 교차로 단계와의 데이터 계약을 문서화한다.
3. Python 생성 파이프라인: import 시 자동 실행과 환경변수 기반의 단계 연결을 명시적인 호출로 옮긴다. 호환 실행 경로는 얇게 유지한다. 실제 기하 fixture를 동일 프로세스에서 서로 다른 출력 위치로 반복 실행하고 결과/상태 격리를 검사한다.
4. 메인 화면: 장면 및 화면 자원 관리의 독립 책임을 모듈로 분리한다. 공유 app.js의 외부 변경을 원문으로 보존하면서 선택 공개용 버전도 검증한다. 기존 사용자 조작/편집 흐름과 자원 정리를 확인한다.
5. 생성 Worker 처리: 신규/편집 생성의 시작·진행률·완료·취소·실패 처리를 공유한다. 오류 상세 유지, 저장 실패 구분, 실패/취소 시 기존 저장본 유지 검사를 추가한다.
6. 백과 화면: 미리보기/썸네일 작업 수명과 목록·필터 책임을 분리한다. 기존 모델 소유권을 다시 변경하지 않는다. 상세 열기·닫기 및 필터 전환을 검사한다.
7. 상태 문서: 현재 완료 상태를 앞에 정리하고 과거 검증 기록을 현재 미완료로 읽지 않도록 표시한다. 다른 대화의 상태 항목은 보존한다.
8. 최종 통합: 선택 변경 manifest/외부 변경 보존 검사, 실제 Python 기하 및 CI 필수 검사, 선택 트리 전체 공개 빌드, 선택 커밋과 push, 호스팅 배포, Edge 공개 신규·기존 동네/편집/백과 확인. 결과와 제한을 기록한다.

## 검토 집중점

- 묶음이 원본보다 오래됐는데도 통과하는 경우: 태스크1 변경 주입 검사.
- 잘린 면이 다중 도형이 되는 경우: 태스크2 실제 기하 경계 검사.
- 여러 동네를 같은 프로세스에서 생성하는 경우: 태스크3 반복 및 실패 후 복구 검사.
- 취소 후 늦은 Worker 응답/저장 실패: 태스크5 이전 저장본과 단일 종료 검사.
- 다른 대화의 app 변경이 선택 커밋에 섞이는 경우: 태스크4·8 원문과 선택 트리 차이 검사.
