# 우리동네 전체 파일 점검

점검일: 2026-11-22. 기준: 현재 작업 폴더와 main. 공개 사이트의 열린 동네·에셋백과 화면도 Edge에서 확인했습니다. 작업 중인 다른 대화의 Codex 제어 기능 변경은 수정·배포하지 않았습니다.

## 결론

역할 분리는 도입되어 있으나 물리적인 소스 분리와 의존 방향 정리는 미완료입니다. 우리동네는 지도 해석·배치·조립 규칙을, 에셋백과는 분류별 등록 정보·모델을 소유하는 방향이 맞습니다. 현재는 같은 domestic-test 안에 생성 로직, 모델 제작 코드, 예전 실험과 비교 화면이 공존합니다. 전체를 지우거나 폴더 이름으로 일괄 이관하면 정식 생성이 깨집니다.

## 조사 범위와 용량

일반 파일 86,635개를 순회하여 경로·바이트·수정시각·Git 추적 여부를 기록했습니다. 외부 archive 심볼릭 링크의 대상은 합산하지 않았습니다. 설치 라이브러리와 Git 내부 파일은 용량 조사 대상이며 모든 내용의 수작업 코드 리뷰 대상은 아닙니다. 실제 실행 경로, 패키징, 등록부, 캐시 정책은 코드로 확인하고 관련 검사를 실행했습니다. 모든 바이너리의 시각적 품질 및 모든 동적 참조까지 검증한 것은 아닙니다.

## 구조 확인

- 분류 7개의 categories/*/catalog.json이 수정 원본입니다. registry.js는 읽기 전용으로 동결하고 삭제·별칭 상태를 반영합니다. category-metadata.js와 상위 catalog.json은 생성 결과입니다.
- assembly-rules/house.js와 asset-policies.js는 동네가 소유하고, 백과 화면은 규칙 설명을 읽습니다. 검사에서 유효 등록 1,023개와 분류 소유권, 기존 정보 보존을 확인했습니다.
- house/generators.js는 아직 korean-facades.js와 facade-textures.js를 재수출하는 연결 파일입니다. 실제 형상 생성기가 전부 백과 아래로 옮겨진 것은 아닙니다.
- details.js는 백과의 창문·문 생성기를 사용하면서 facilities/models.js, rooftops.js, korean-facades.js도 직접 가져옵니다. 에셋 생성기와 배치·표현 코드 경계가 혼재합니다.
- 백과 models.js도 바깥의 tree-planting.js와 shops/interiors.js 등과 연결됩니다. 공유 코드를 백과 소유 모델 생성 API와 공통 렌더러로 정리할 필요가 있습니다.
- 정식 pack.py는 work/house-plots-test의 13개 Python 파일과 work/windows-v39/terrain-functions.js.txt, work/arterial-v76의 정류장 자료를 사용합니다. 오래된 이름이어도 폐기본이 아닙니다. 현재 공개 생성 묶음 52개 파일은 원본과 일치합니다.
- build-site.py는 outputs 아래 Git에 등록된 파일을 넓게 복사하고 일부만 제외합니다. 실행에 필요한 파일을 명시적으로 고르는 방식이 아니므로 옛 비교 페이지를 Git에 추가하면 배포에 포함될 가능성이 있습니다.

## 캐시·옛 버전

- outputs HTML/JS 검색에서 serviceWorker 등록과 CacheStorage 사용 코드를 찾지 못했습니다. 이는 사용자의 브라우저에 과거 서비스워커가 절대 없다는 검증은 아닙니다.
- 저장 동네는 browserGenerationVersion=11, ruleset, visible360 버전 3 및 위치·크기·눈높이를 검사해 재사용합니다. client.js는 VWorld 출처와 교차로 버전도 확인합니다. 옛 반경 생성본을 무조건 최신 결과로 재사용하는 구조는 아닙니다.
- 먼 건물 지도 캐시는 별도 DB(v2), 유효기간 7일, 보관 상한 128개입니다. 이것은 생성 결과 전체가 아닌 지도 건물 자료 캐시입니다.
- 저장 동네는 사용자 편집을 포함하므로 캐시처럼 일괄 삭제하지 않았습니다. 브라우저의 실제 저장 용량·전체 레코드·HTTP 캐시 내용은 이번에 조회하지 않았습니다.
- dist와 현재 추적 소스 사이에서 57개 파일의 내용 차이를 확인했습니다. 최적화로 의도적으로 달라진 파일도 포함되므로 전부 오래된 파일이라는 뜻은 아닙니다. dist를 현재 원본으로 사용하면 안 됩니다. 정상 빌드는 dist를 지우고 다시 만듭니다.
- 이전 검사 폴더에는 옛 Documents/Codex 배포 경로로 향하는 링크가 있었습니다. 현재 검사·실행 코드에서 참조를 찾지 못하여 분리했습니다.

## 실제 정리

verification/file-audit-20261122/retired/ 아래로 11개 경로, 총 1,350,331바이트를 이동했습니다. 24시간 이상 지난 프로젝트 Python 캐시 10곳과 과거 배포 검사 폴더 1곳입니다. 원본 Python 파일과 설치 환경, 진행 중 제어 기능의 캐시는 보존했습니다. 새 캐시는 필요할 때 자동 생성됩니다.

moves.json에 원래 위치·보관 위치·사유를 기록했습니다. 삭제가 아닌 이동이므로 디스크 총량을 줄인 작업은 아닙니다. 보관 폴더는 Git 등록에서 제외했습니다. 모델, 참고 이미지, 승인 자료, 기존 고정 ID, 저장 지도, 검증에 직접 쓰는 자료는 이동하지 않았습니다. 백업 전체를 외부 보관 폴더로 옮기는 작업과 옛 실험 소스의 완전 분리는 완료하지 않았습니다.

## 리팩토링 우선순위

1. 오래된 참고 이미지 검사를 현재 18+50 구조에 맞게 갱신하고 승인 기록의 ID 일치를 유지합니다.
2. 배포 대상을 명시 목록으로 만들고 등록부 모델·동적 import·기존 URL 호환 파일을 포함하는 누락 검사를 추가합니다. 옛 비교 화면이 실수로 배포되는 것을 막는 우선 조치입니다.
3. 백과의 분류별 모델 생성 API를 실제 구현의 주인으로 만들고 동네의 직접 생성기 참조를 통일합니다. 환경·조명·공통 렌더링은 공통 계층으로 유지합니다.
4. house-plots-test 중 실제 쓰는 13개 모듈을 정식 생성 폴더로 옮기고 기존 import 호환 및 pack.py를 함께 갱신합니다. 이를 마친 뒤 실험 결과를 별도 보관합니다.
5. PROJECT_STATE.json과 project-layout.txt의 현재 상태와 날짜별 역사를 구분합니다. 현재 상태 파일은 약 253KB로 과거 기록이 누적되어 있습니다.
6. 생성 규칙 변경 시 저장 동네의 버전·에셋 계약 버전 갱신을 검사로 강제합니다. 브라우저 저장 내용은 수동 편집 보존을 전제로 명시적 재생성 흐름을 유지합니다.

이번 변경은 로컬 보관 정리와 감사 기록뿐이며 공개 실행 코드를 바꾸지 않았습니다. 따라서 새 배포는 하지 않았습니다. 다른 대화의 미완료 변경을 포함한 배포도 하지 않았습니다. 완전한 두 영역 재구성과 전체 옛 자료 이관은 별도 구현 작업으로 남습니다.
